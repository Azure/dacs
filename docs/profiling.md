# CPU Profiling with `kubectl-prof`

[kubectl-prof](https://github.com/josepdcs/kubectl-prof) profiles applications running in Kubernetes pods with zero modifications. It launches a privileged agent Job on the target pod's node, runs `perf` (or eBPF), and streams the results back to your machine.

## Prerequisites

Install `kubectl-prof`:

```bash
make install-kubectl-prof
```


## Quick start

```bash
# Profile all CacheServer pods for 2m while running a perf test in another terminal
make perf-record-server

# In another terminal, start the workload:
make test-perf EXTRA_TEST_ARGS="--data-size-gib=100 --num-threads=64"
```

The raw output is saved to `perf-results/server/` and flamegraph SVGs are generated automatically. Open them in a browser — they're interactive (click to zoom, search with Ctrl+F).

## Make targets

| Target | Description |
|--------|-------------|
| `make perf-record-server` | Profile all CacheServer pods (by label selector) |
| `make perf-record-client` | Profile all PerfClient pods (by label selector) |
| `make install-kubectl-prof` | Install kubectl-prof binary |

## Configuration

All options can be set via Make variables or environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `PERF_DURATION` | `2m` | Recording duration (e.g. `30s`, `2m`, `5m`) |
| `PERF_NAMESPACE` | `cache-server` | Kubernetes namespace |
| `PERF_OUTPUT_DIR` | `./perf-results` | Output directory |
| `PERF_LANG` | `clang++` | Language: `clang`, `clang++`, `go`, `python`, `java`, etc. |
| `PERF_SERVER_LABEL` | `app=cacheserver` | Label selector for `perf-record-server` |
| `PERF_CLIENT_LABEL` | `app=perf-client` | Label selector for `perf-record-client` |

Example with custom settings:

```bash
make perf-record-server PERF_DURATION=5m
```

## Using kubectl-prof directly

The Make targets are thin wrappers. You can call `kubectl prof` directly:

```bash
# Profile all CacheServer pods with raw output
kubectl prof --selector app=cacheserver -n cache-server -t 2m -l clang++ -o raw --tool perf

# Generate flamegraph from raw output
.local/FlameGraph/flamegraph.pl perf-results/server/*.txt > flamegraph.svg

# Profile a single pod directly
kubectl prof cacheserver-0 -n cache-server -t 2m -l clang++ -o flamegraph --tool perf

# Profile PerfClient pods
kubectl prof --selector app=perf-client -n cache-server -t 2m -l clang++ -o raw --tool perf
```

## Output files

After recording with `raw` output, the directory contains:

```
perf-results/server/
├── cacheserver-0-agent-raw-*.txt   # Raw collapsed stacks per pod
├── cacheserver-0-agent-raw-*.svg   # Flamegraph per pod (generated by Make)
├── cacheserver-1-agent-raw-*.txt
└── cacheserver-1-agent-raw-*.svg
```

The flamegraph shows where the process spends CPU cycles. Wide stacks = hot code paths.

## Typical workflow

```bash
# 1. Deploy cache server
make deploy

# 2. Start profiling (in terminal 1)
make perf-record-server PERF_DURATION=3m

# 3. Run workload (in terminal 2)
BUILD_NUMBER=latest DOCKER_REGISTRY=myregistry.azurecr.io \
  make test-perf EXTRA_TEST_ARGS="--data-size-gib=100 --num-threads=64"

# 4. Wait for profiling to finish, then open the flamegraphs
open perf-results/server/*.svg
```
